**Consumers of the new API**
Grepping `loadCampaign|discoverCampaigns|availableInspirations|validateCampaign` and `plateDirection|plate_direction|campaign.copy|cta_href` shows the only importers are the test file and the campaign JSONs themselves. The validated campaign fields do not yet reach any sink in the repo — no LLM prompt, no HTML renderer, no fetch of `cta_href`, no shell/SQL, no filesystem write keyed on user data.

**Sinks I checked and cleared**
- `readFileSync(path, 'utf8')` in `loadCampaign` — `path` comes from `discoverCampaigns(join(dir, f))` where `f` is filtered by `.endsWith('.json')` from a fixed campaigns dir, or from tests that construct their own temp path. Not attacker-influenced.
- `walk()` in `availableInspirations` uses `statSync` (follows symlinks), so a symlink cycle under an attacker-writable inspirations root would cause unbounded recursion. But the root is a repo-relative constant (`PACKET`) reached only from tests; no external caller supplies it.
- `JSON.parse` on fixture files — no prototype pollution vector because `raw.*` values are read as own properties and no target object is merge-assigned; and Node's `JSON.parse` places `__proto__` as an own property rather than mutating the prototype.
- The duplicate-canvas gate (`seen.has(...)` before `seen.add`) is ordered correctly.
- No `+` line introduces a logging/telemetry sink for sensitive data; `plate_direction` and `messages` echo back into `detail` strings, but only the validator's own return value — not a log, span, or external egress.
- `mkdtempSync`/`rmSync(recursive:true,force:true)` in tests operate on paths returned by `mkdtempSync` itself, so no path-traversal / arbitrary-delete concern.

**Regression / sibling-parity / IPC / policy-gate patterns** — none applicable; no existing security controls are touched, no auth surface, no cross-principal boundary.
